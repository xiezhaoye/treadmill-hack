## 这是什么

很多跑步机只能用厂商 App 控制，数据也锁在厂商云端。本项目把控制权拿回来：

- ✅ **启动 / 暂停 / 停止**
- ✅ **调节速度**（精确到 0.01 km/h）
- ✅ **调节坡度**
- ✅ **实时读取**速度、坡度、时间、距离、步数
- ✅ 不需要 root，不需要改装硬件
- ✅ 可接入 Home Assistant（ESP32 方案）

**适用条件**：你的跑步机支持蓝牙，且厂商 App 用的是**标准 FTMS 协议**（大部分现代跑步机都是）。

## 快速开始

### 你需要

1. 一台 Android 手机（用来抓包 + 中转，Android 7+）
2. 跑步机
3. 电脑（Mac / Linux / Windows 都行，装了 `adb`）

### 三步走

```bash
# 第 1 步：抓包（了解你的跑步机协议）
#   手机上开「蓝牙数据包日志」，用厂商 App 连一次跑步机、操作几下
#   然后取出 btsnoop 文件分析
./tools/pull-btsnoop.sh          # 自动从手机拉取
./tools/parse-btsnoop.py         # 解析出 GATT 通信

# 第 2 步：装 BLE Relay（在手机上执行控制指令）
./tools/build-android.sh         # 编译 APK（15 KB）
adb install android/relay.apk

# 第 3 步：控制
adb shell am start -n com.treadmill.relay/.Main -e target <你的跑步机名>
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd 00    # Request Control
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd 07    # Start
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd 02f401 # 速度 5.0
```

## 核心发现

### 1. 现代跑步机大多用标准 FTMS

**FTMS** = Fitness Machine Service（Bluetooth SIG 标准，UUID `0x1826`）

控制点是 `0x2AD9`，指令是标准化的：

| 指令 | 功能 |
|---|---|
| `00` | Request Control（**必须先发**） |
| `07` | Start / Resume |
| `0801` | Stop / Pause |
| `02<lo><hi>` | Set Speed（×100，小端） |
| `03<lo><hi>` | Set Inclination（×10，小端） |

详见 [docs/02-FTMS协议参考.md](docs/02-FTMS协议参考.md)。

### 2. 但很多厂商加了"解锁码"

我测的 YPOO M5 需要先写一个解锁码，否则所有指令返回 `05`（Invalid Parameter）：

```
写 0123456789ABCDEF → d18d2c10-c44c-11e8-a355-529269fb1459
```

**这个码从哪里来？** 两种方式：

1. **从 App 数据里提取**（`adb backup`，见 [docs/01](docs/01-协议逆向完整记录.md)）
2. **从跑步机二维码解析**（我的二维码里有 `k=008B87`）

### 3. 三个致命细节（缺一不可）

| # | 细节 | 不做的后果 |
|---|---|---|
| 1 | 先写解锁码 | 所有指令返回 `05` 被拒 |
| 2 | 解锁后**等 2 秒** | 跑步机重置 GATT 会话，订阅失效 |
| 3 | **逐个订阅**特征值 | 一次性订阅多个会失败，**收不到任何数据** |

第 3 条是最隐蔽的坑——我用了几小时才发现（Android 的 GATT 队列一次只能处理一个 descriptor 写入）。

## 实测数据（YPOO M5）

### 控制指令

```
启动   00 → 07 → 02f401(5.0km/h) → 032800(4.0%)
停止   0801
```

### 返回的实时数据（每 0.45 秒一帧）

```
9c25 f401 0000 0028 00ff7f 0100 00000000 1200 0000 0600 0000 00
     ↑         ↑
     速度      坡度
     f401=500  0028=40
     ÷100       ÷10
     =5.00km/h =4.0%
```

### 平滑停车验证

```
ea01(490) → c201(450) → 9001(400) → 6801(360) → 3601(310) → 0e01(270) → dc00(220) → 0000(0)
```

跑步机自己按安全步长降速，不需要程序控制曲线。

## 两种落地方式

### 方式 A：手机中转（快速验证）

```
电脑 ──adb── 手机 ──BLE── 跑步机
```

优点：零成本、立刻能用
缺点：占用手机、App 会抢连接、不能长期挂机

### 方式 B：ESP32 + ESPHome（长期方案）

```
Home Assistant ──WiFi── ESP32 ──BLE── 跑步机
```

优点：7×24 挂机、接入 HA、可自动化
成本：约 ¥50（ESP32-S3 开发板）

配置见 [esphome/treadmill.yaml](esphome/treadmill.yaml)。

## 自动记录（免操作）

**问题**：跑步机本身**不存历史**。断电就清零，FTMS 协议里也没有历史记录字段。

厂商 App 的记录是**上传到服务器**的，你换账号/厂商关服就没了。

**解法**：用 ESP32 常驻监听，自动识别跑步会话。

```
跑步机静止时也在推送数据（每秒 2.2 帧）
         ↓
ESP32 监控速度字段
         ↓
速度 0 → 非0（持续 3 秒）  = 会话开始
速度 非0 → 0（持续 60 秒） = 会话结束
         ↓
结算：时长 / 距离 / 均速 / 最高速 / 坡度范围
         ↓
Home Assistant 自动存库 + 手机推送通知
```

**用户完全不需要任何操作**——按跑步机按钮开始跑，跑完自动记录。

配置见 [esphome/auto-session.yaml](esphome/auto-session.yaml)。

> ⚠️ 距离计算目前用「速度×时间」积分近似（帧内累计距离的字节偏移尚未完全验证）。
> 精确标定方法见 [tools/analyze-frames.py](tools/analyze-frames.py)。
