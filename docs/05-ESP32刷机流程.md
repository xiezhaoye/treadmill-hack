# ESP32 刷机流程

> 从零到 Home Assistant 可控，全程约 30 分钟。

---

## 一、收货先验证（10 分钟）

**⚠️ 别急着刷，先确认板子是真货。**

市面上有贴牌板（N8R2 冒充 N16R8）。验证方法：

### 1.1 插上电脑

```bash
ls /dev/cu.usb*
# macOS 会看到类似:
#   /dev/cu.usbmodem1101    (原生 USB)
#   /dev/cu.wchusbserial1420 (CH340 转串口)
```

**记住这个端口名**，后面一直用。

### 1.2 装 esptool

```bash
pip install esptool
# 或 brew install esptool
```

### 1.3 读芯片信息

```bash
# 换成你的端口
PORT=/dev/cu.usbmodem1101

esptool.py --port $PORT chip_id
esptool.py --port $PORT flash_id
```

**期望输出**：
```
Chip is ESP32-S3 (QFN56) (revision v0.2)
Features: WiFi, BLE
Crystal is 40MHz
MAC: xx:xx:xx:xx:xx:xx

Detected flash size: 16MB        ← 必须是 16MB
```

**如果是 8MB，说明你买到的是 N8R2**，找卖家换货。

### 1.4 确认 PSRAM

esptool 不一定显示 PSRAM，最可靠是**刷完 ESPHome 后看日志**：

```
[I][esp32.preferences:xxx]: PSRAM: 8MB (octal)   ← 期望
```

如果是 `2MB` 或 `not found`，是 N8R2。

## 二、装 ESPHome（5 分钟）

### 2.1 方式 A：装在 109nas（推荐，Docker）

```bash
# SSH 到 109nas
ssh admin@192.168.199.109

mkdir -p /volume1/docker/esphome
cd /volume1/docker/esphome

cat > docker-compose.yml <<'EOF'
services:
  esphome:
    container_name: esphome
    image: ghcr.io/esphome/esphome:latest
    volumes:
      - ./config:/config
      - /etc/localtime:/etc/localtime:ro
    ports:
      - "6052:6052"
    restart: unless-stopped
    network_mode: host
EOF

docker-compose up -d
```

访问 `http://192.168.199.109:6052`（或群晖的实际 IP）。

### 2.2 方式 B：装在 Mac 上（临时用）

```bash
pip install esphome
esphome dashboard ~/esphome --open-ui
```

### 2.3 方式 C：纯命令行（最快）

```bash
pip install esphome
cd ~/project/treadmill-hack/esphome
cp secrets.yaml.example secrets.yaml
# 编辑 secrets.yaml 填 wifi 密码等
esphome config treadmill.yaml     # 校验配置
esphome run treadmill.yaml        # 编译+烧录
```

## 三、准备配置（3 分钟）

### 3.1 复制 secrets

```bash
cd ~/project/treadmill-hack/esphome
cp secrets.yaml.example secrets.yaml
```

编辑 `secrets.yaml`：

```yaml
wifi_ssid: "xiaoyuan_5G"          # ⚠️ 必须是 2.4GHz！
wifi_password: "你的密码"
ap_password: "fallback123"
api_key: "..."                     # 见下
ota_password: "ota456"
```

**生成 api_key**：
```bash
openssl rand -base64 32
```

### 3.2 ⚠️ WiFi 必须是 2.4GHz

ESP32 **不支持 5GHz WiFi**。

你家用的是 `xiaoyuan_5G`（从抓包看到）——如果路由器有 2.4G 频段（SSID 通常是 `xiaoyuan` 不带 5G 后缀），**要连 2.4G 那个**。

**检查方法**：
- 看路由器管理页
- 或手机上搜 WiFi，看有没有不带 `_5G` 的同名网络

**如果只有 5GHz**：
- 路由器后台开一个 2.4GHz 频段
- 或者用 ESP32 的 fallback AP 模式（但那样就没法接 HA 了）

### 3.3 填跑步机信息

编辑 `treadmill.yaml` 顶部的 `substitutions`：

```yaml
substitutions:
  treadmill_mac: "AA:BB:CC:DD:EE:FF"        # 你的跑步机 MAC
  unlock_code: "0123456789ABCDEF"           # 解锁码
  device_name: "balcony-treadmill"
  oled_sda: "GPIO8"                         # 看你的板子丝印
  oled_scl: "GPIO9"
```

**MAC 从哪来**：
```bash
# 用手机 App 连上跑步机后，在 logcat 里看
adb logcat | grep -i "AA:BB:CC"   # 换成你的 MAC 前缀
# 或看本仓库 docs/01 的方法
```

**解锁码从哪来**：
1. **从 App 数据提取**（推荐）：
   ```bash
   adb backup -f app.ab -noapk <厂商App包名>
   # 解包后看 apps/<包名>/f/mmkv/mmkv.default 里的 unlock_code
   ```
2. **从跑步机二维码**：参数里的 `k=` 可能是
3. **先试空**：有些跑步机不需要解锁，把 `unlock_code` 留空或注释掉 `btn_unlock` 测试

## 四、烧录（5 分钟）

### 4.1 首次刷机（USB）

```bash
cd ~/project/treadmill-hack/esphome

# 校验配置（会报错就修）
esphome config treadmill.yaml

# 编译 + 烧录（第一次必须用 USB）
esphome run treadmill.yaml
```

**会问你设备**：
```
INFO Choose your device:
  [1] /dev/cu.usbmodem1101
  [2] Over The Air (balcony-treadmill.local)
```
**选 1（USB）**。

### 4.2 后续升级（OTA）

改完配置后：

```bash
esphome run treadmill.yaml
# 选 2（Over The Air），不用插线
```

## 五、验证（5 分钟）

### 5.1 看日志

```bash
esphome logs treadmill.yaml
```

**期望看到**：
```
[I][app:xxx]: ESPHome version 2024.x.x
[I][wifi:xxx]: WiFi Connected!  IP: 192.168.199.xxx
[I][ble_client:xxx]: BLE client connected to AA:BB:CC:DD:EE:FF
[I][treadmill:xxx]: 跑步机已连接
```

**关键确认 3 件事**：

| 检查 | 期望 |
|---|---|
| WiFi 连上 | `IP: 192.168.199.xxx` |
| BLE 连上 | `BLE client connected` |
| PSRAM | `PSRAM: 8MB (octal)` |

### 5.2 手动测试（在 HA 里）

1. 打开 Home Assistant
2. 设置 → 设备与服务 → 应该自动发现 `balcony-treadmill`
3. 点「配置」→ 输入 `api_key`
4. 设备页里会看到：
   - 按钮：解锁 / 请求控制 / 启动 / 暂停 / 停止 / 一键启动
   - 数字：速度 / 坡度
   - 传感器：当前速度 / 当前坡度 / 信号强度
   - 二进制：已连接

**测试顺序**：
```
① 确认「已连接」= on
② 点「解锁」→ 看日志有 "写解锁码"
③ 等 2 秒
④ 点「请求控制」→ 看日志
⑤ 点「启动」→ 跑步机动了？
⑥ 调「速度」= 2.0 → 跑步机变速？
⑦ 点「停止」
```

### 5.3 一键启动（最省事）

直接点「**一键启动**」，它会自动：
```
写解锁码 → 等 2s → Request Control → Start
```

## 六、ROS 排查

### 6.1 烧录失败

| 现象 | 解决 |
|---|---|
| `Failed to connect` | 按住 BOOT 键再插 USB，或换数据线 |
| `A fatal error occurred: MD5 of file does not match` | 重新插拔，可能线接触不良 |
| 端口找不到 | 装 CH340 驱动（macOS 通常免驱） |

### 6.2 WiFi 连不上

| 现象 | 原因 |
|---|---|
| 一直重连 | **连了 5GHz**，改用 2.4G |
| 连上但没 IP | 路由器 DHCP 满了 |
| 密码错误 | secrets.yaml 里含有特殊字符要加引号 |

**临时救急**：ESP32 会开 `balcony-treadmill-fallback` 热点，连上去配置。

### 6.3 BLE 连不上跑步机

| 现象 | 原因 | 解决 |
|---|---|---|
| `BLE client not connected` | 跑步机被手机 App 占着 | 手机 `am force-stop <App>` |
| 扫不到设备 | 距离太远 | ESP32 靠近跑步机 |
| 连上但没数据 | **没有顺序订阅** | 见下 |

**⚠️ 最重要的坑**：ESPHome 的 `ble_client` **不支持手动逐个订阅**，它自动一次性订阅所有 notify 特征值。

如果收不到数据，需要：
1. 确认 `notify: true` 已设置
2. 或用 `on_value` 里的日志确认是否有数据

**实测**：ESPHome 的 BLE 栈底层实现不同（ESP-IDF 原生），**可能不受 Android 那个 GATT 队列限制的影响**——这也正是用 ESP32 而不是手机的理由之一。

### 6.4 指令发了但跑步机不动

| 检查 | 做法 |
|---|---|
| 解锁码对吗 | `esphome logs` 看有没有写成功 |
| 是不是要等 2 秒 | 用「一键启动」按钮（内置了 delay） |
| 速度超范围 | 先读 `0x2AD4`（Supported Speed Range） |
| 协议不对 | 用 `tools/parse-btsnoop.py` 重新抓包对比 |

## 七、常用命令

```bash
# 看配置
esphome config treadmill.yaml

# 编译（不烧录）
esphome compile treadmill.yaml

# 烧录（USB）
esphome upload treadmill.yaml --device /dev/cu.usbmodem1101

# OTA 升级
esphome run treadmill.yaml

# 看日志
esphome logs treadmill.yaml

# 清理编译缓存（配置大改后建议）
rm -rf .esphome
```

## 八、恢复出厂

如果板子刷坏了或想重来：

```bash
# 完全擦除
esptool.py --port /dev/cu.usbmodem1101 erase_flash

# 重新刷
esphome run treadmill.yaml
```

**按住 BOOT 键插 USB** 可以强制进下载模式（刷成砖也能救）。
