# 架构图

两类部署方式，原理相同：**任何能跑 BLE 客户端的设备都可以做控制器**。

---

## 一、核心原理

协议在 App 里，但 **BLE 是公开的**。只要学会"说同样的话"，任何设备都能控制跑步机。

```
┌──────────────────────────────────────────────────────────────┐
│                        跑步机（BLE 外设）                     │
│                                                              │
│  GATT 服务 0x1826 (FTMS)                                     │
│  ├─ 0x2AD9 控制点 ← 收指令（00/07/02xx/03xx/0801）           │
│  ├─ 0x2ACD 数据   → 推状态（速度/坡度/时间）                  │
│  └─ 解锁通道      ← 首条指令，否则一切被拒                     │
└──────────────────────────────────────────────────────────────┘
              ▲                              │
              │ 写指令                        │ 通知数据
              │                              ▼
┌──────────────────────────────────────────────────────────────┐
│                    控制器（BLE 客户端）                       │
│  可以是：Android 手机 / ESP32 / 树莓派 / 另一台电脑            │
└──────────────────────────────────────────────────────────────┘
```

## 二、方案 A：手机中转（快速验证）

适合：**想先验证协议对不对**，零成本。

```
┌─────────────┐   USB / WiFi   ┌──────────────┐      BLE      ┌──────────┐
│   电脑       │ ─────────────► │  Android 手机 │ ────────────► │  跑步机   │
│  (adb 控制)  │   端口 5555     │  BLE Relay   │   GATT 读写   │          │
└─────────────┘                └──────────────┘               └──────────┘
      │                               │
      │ adb shell am broadcast        │ 数据回传
      │ -e cmd "02f401"               │ (logcat / 文件)
      ◄───────────────────────────────┘
```

### 工作流程

```bash
# 1. 手机连跑步机（BLE Relay 保持长连接）
adb shell am start -n com.treadmill.relay/.Main -e target AA:BB:CC:DD:EE:FF

# 2. 自动：解锁 → 等2秒 → 顺序订阅 8 个特征值

# 3. 发指令
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd "00"      # Request Control
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd "07"      # Start
adb shell am broadcast -a com.treadmill.relay.SEND -e cmd "02f401"  # 速度 5.0

# 4. 读实时数据
adb logcat | grep "★ 通知"
# → 9c25 f401 0000 0028 00ff7f ...  (速度 500, 坡度 40)
```

### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---|---|
| 零成本，立刻能用 | 占用一台手机 |
| 不用额外硬件 | 厂商 App 会抢连接 |
| 改代码方便 | 不能 7×24 挂机 |
| | Android 后台保活难 |

### 优缺点

| ✅ 优点 | ❌ 缺点 |
|---|---|
| 7×24 挂机 | 需要买硬件（¥50-70） |
| 不占手机 | 需要一次刷机 |
| 接入 HA 做自动化 | 受 BLE 连接数限制（3-5 个主动连接） |
| 同时做蓝牙网关/红外/传感器 | |
| OTA 升级，不用反复插线 | |

## 四、为什么 Mac 不能直接连

**两个硬限制：**

### 4.1 物理距离

```
书房 ─────── 阳台
 电脑          跑步机
   ↑
  BLE 有效距离 10 米级，隔墙更短
  连不上
```

### 4.2 扫描不到

实测（macOS BCM_4387）：
```
扫描 15 秒 → 17 个 BLE 设备（iPhone/Apple TV/音箱/温湿度计…）
关键字匹配 YPOO/M5 → 无
```

原因：**跑步机被手机 App 连着时不广播**，且它是 App 专属私有通道。

## 五、数据流详解

### 5.1 控制指令（下行）

```
Home Assistant / adb
        │
        │ "02f401"  (速度 5.0)
        ▼
   控制器（手机/ESP32）
        │
        │ ATT Write Request
        │ handle 0x029 (0x2AD9)
        │ 数据: 02 f4 01
        ▼
     跑步机 ── 解析 opcode 0x02 = Set Target Speed
        │     uint16 小端 = 0x01F4 = 500
        │     500 ÷ 100 = 5.00 km/h
        ▼
   跑带加速到 5.0 km/h
```

### 5.2 状态数据（上行）

```
跑步机
   │ ATT Handle Value Notification
   │ handle 0x025 (0x2ACD)
   │ 9c25 f401 0000 0028 00ff7f 0100 00000000 1200 0000 0600 0000 00
   ▼
控制器
   │
   │ 解析：
   │   [0:2]  = 9c25    帧头
   │   [2:4]  = f401    → 500 ÷ 100 = 5.00 km/h
   │   [4:6]  = 0028    → 40 ÷ 10 = 4.0%
   │   [0x10] = 1200    → 时间/距离（递增）
   ▼
Home Assistant 实体
   sensor.treadmill_speed   = 5.00
   sensor.treadmill_incline = 4.0
```

### 5.3 连接建立时序（关键！）

```
控制器                              跑步机
   │                                  │
   ├──── BLE 扫描 ────────────────────►
   │◄─── 广播包（含名字/MAC）──────────┤
   │                                  │
   ├──── Connect ─────────────────────►
   │◄─── CONNECTED ────────────────────┤
   │                                  │
   ├──── Discover Services ───────────►
   │◄─── 服务/特征值列表 ───────────────┤
   │                                  │
   ├──── 写解锁码 ────────────────────►   ★ 第一步！
   │    (d18d2c10-...)                │
   │                                  │
   │        ⏱ 等 2 秒                  │   ★ 第二步！
   │    (跑步机重置 GATT 会话)          │
   │                                  │
   ├──── 订阅特征值[0] ───────────────►   ★ 第三步
   │◄─── CCCD 写入成功 ────────────────┤   逐个订阅！
   ├──── 订阅特征值[1] ───────────────►
   │◄─── CCCD 写入成功 ────────────────┤
   │         ... （共 8 个）            │
   │                                  │
   ├──── Write 0x2AD9 = 00 ──────────►   Request Control
   │◄─── Indicate 800001 ─────────────┤   成功
   │                                  │
   ├──── Write 0x2AD9 = 07 ──────────►   Start
   │◄─── 开始推送 2ACD 数据 ───────────┤
```

## 六、快速决策表

| 你的情况 | 选哪个 |
|---|---|
| 只想验证协议能不能用 | **方案 A**（手机） |
| 想长期挂机、接入 HA | **方案 B**（ESP32） |
| 不想买硬件 | 方案 A |
| 手机不想被占用 | 方案 B |
| 想做自动化（晨跑提醒等） | 方案 B |
| 还有别的蓝牙设备要接 | 方案 B（顺带做蓝牙网关） |
